## What it is

Protocol-independent plumbing around `client.Client`: it contains no SMB/FTP/NFS/WebDAV code, so every present and future protocol client inherits it.

| Piece | File | Behaviour |
|---|---|---|
| `HostBudget`, `Budgets` | `budget.go` | per-host cap: `MaxConcurrent` operations in flight and `MaxReqPerSec` evenly spaced starts (no burst, idle time is not banked). A start slot reserved by a caller whose context ends while it waits is **given back** (the schedule front is wound back, also when the returned slot was a reused one that became the tail, or the slot is reused by the next caller if it is still in the future), and a caller whose deadline falls before its slot fails fast without reserving (the error wraps `ErrBudgetBusy` and `context.DeadlineExceeded`, so "the budget is saturated" is distinguishable from "my context ended"); so cancelled waiters never push the schedule ahead of real time. `TryAcquire` takes a slot only if one is free AND the start slot is due right now, never waits and never reserves. A rate whose spacing does not fit a `time.Duration` (below about 1.1e-10 per second) is rejected, never turned into "no spacing". `Budgets.For(host, cfg)` returns ONE budget per host key (`HostKey`), so SMB and SFTP to the same NAS share the cap. Both limits are required and positive (no silent default); `NASBudget()` (4 and 10/s) is an explicit opt-in. A different config for an already registered host is `ErrBudgetConflict`. `WithStreamLease(d)` optionally releases the slot of a stream that has been **idle** for `d`. The cap bounds **operations and open streams** in this process, not TCP connections: the connection count is the pool's `MaxPerKey` per storage root. **What the cap covers**: every operation taken through `Limited`, including the connection probe (taken without waiting, see `Limited`). **What it does not cover**: `Disconnect` (closing must always be possible), the local calls `IsConnected` / `GetProtocol` / `GetConfig`, and a stream that has been idle past its lease. |
| `BudgetStats` | `budget.go` | `InFlight` = held concurrency slots, including callers still sleeping for their start slot. `Acquired` = start-slot **reservations**, including ones later given back because the caller's context ended (it is not the number of operations the host saw). `TotalRateWait` = wait imposed at reservation time. `Held` / `OldestHeld` = slots held by callers that finished waiting (running operations and open streams) and the age of the oldest, so a leaked stream is visible. `LeaseExpired` = slots taken back by the lease. |
| `Pool` | `pool.go` | implements `client.ConnectionPool`. Per storage root (`StorageConfig.ID`): `MaxPerKey` cap (**per root, not per host**: N roots on one NAS can hold N x `MaxPerKey` connections, bound the host with a `HostBudget`), health check on borrow (`IsConnected` and `TestConnection` with `HealthTimeout`; a probe skipped by a busy budget is not a fault), `MaxLifetime` and `IdleTimeout` retirement, `GetClient` and `GetClientContext`, `Evict`, idempotent `CloseAll`, double or foreign return is `ErrNotFromPool`, a client the factory hands out twice is `ErrDuplicateClient`. Details below. |
| `Limited(c, budget)` | `limited.go` | every operation takes a budget slot; read streams (`ReadFile`, `OpenSeekable`) keep it until `Close`. `Disconnect` is the one budget-exempt call (closing must always be possible). `TestConnection`, the pool's health probe, is budgeted **without waiting** (`HostBudget.TryAcquire`): with a free slot and a due start slot it runs inside `MaxConcurrent` and the rate; otherwise it is **not run** and returns `ErrProbeSkipped`. It is not exempt because for some protocols a probe is not cheap (SMB lists the share root, WebDAV sends a PROPFIND), and it must not wait or error because a busy host would then block `GetClient` or retire a good connection. `Connect` is budgeted (a login). A stream that is never closed keeps its slot, across all protocols of the host, unless the budget was built with `WithStreamLease` (idle-based). |
| `Retrying(c, policy)` | `retrying.go`, `errors.go` | repeats READ operations only, with exponential backoff, after errors classified transient. Never retries: mutations, `Disconnect`, authentication failures, permanent or unrecognised errors, or after the caller's context is done. The policy is validated: `MaxAttempts` 1..`MaxRetryAttempts` (100), and `BaseDelay` > 0 whenever `MaxAttempts` > 1 (a zero delay is a retry storm). The delay actually used is never below `MinRetryDelay` (10 ms): a smaller base or cap, or a `Jitter` that returns 0, is raised to it, because a 1 ns delay is the same back-to-back storm. Exhaustion wraps the last error with `ErrRetriesExhausted`. See "Error classification". |
| `Confined(c, root)` | `confined.go` | paths are normalised (backslash is a separator, every Unicode control character (category Cc) is refused - NUL, CR, LF, ESC, the rest of C0, DEL and the C1 controls U+0080..U+009F such as NEL and CSI - and so is any byte sequence that is not valid UTF-8, relative paths resolve under root, `path.Clean`) and must stay inside root at a segment boundary; the inner client receives the cleaned path; escapes are `ErrOutsideRoot` and never reach it; `CopyFile` checks both paths first. The check is **lexical** (see Limits). |
| `Metered(c, sink, clock)` | `metered.go` | one `Sample` per operation (streams are reported at `Close` with the bytes read through `Read`, `ReadAt` and `WriteTo`; `WriteFile` counts bytes consumed). `CounterSink` is the dependency-free aggregate; the catalog-api metrics package can implement `Sink`. |
| `Op` table, `HostKey` | `op.go` | the single reviewed classification of every operation (mutating, retryable, stream, path arity). `HostKey` accepts a host, `host:port` or `[ipv6]:port` only (a URL, path, `user@host`, an unterminated bracket, text after the closing bracket, a bracketed name, a non-numeric or out-of-range port, or several colons that are not an IPv6 literal is an error), canonicalises IP literals (RFC 5952 text, IPv4-mapped IPv6 unmapped) and does **not** resolve names: `nas`, `nas.local` and the machine's IP are three keys. |
| `guard` (package `pkg/decorators/guard`) | `nil.go`, `config.go`, `stream.go` | shared helpers: typed-nil detection (every decorator and `ReadOnly` panic at construction for a typed nil too), `RedactConfig` (deep copy, secrets blanked at any depth) and the capability-preserving stream wrapper (a nil or typed-nil stream stays nil; `WriteTo` is reported while it copies). |

Every decorator preserves `client.SeekableClient` iff the inner client has it, and none embeds the interface (a new interface method breaks the build instead of being promoted unguarded). The streams they return preserve the inner stream's `io.Seeker`, `io.ReaderAt` and `io.WriterTo`, so a consumer that type-asserts `io.ReaderAt` (catalog-api's comic page handler) still gets ranged reads through any layer. `GetConfig` of every layer is a redacted, detached copy (see [pkg_decorators.md](pkg_decorators.md)).

## Pool behaviour

- **Cancellation is not a health verdict.** A context that is already done never reaches the pool; if the caller's context ends during the health probe, the probed connection is put back and the context error is returned. Only a probe failure under a live context retires the connection.
- **No repeated logins after a rejected one, single-flight, per account.** A login whose error says the ACCOUNT's credentials were refused is remembered (as a hash, never the settings) and further borrows fail fast with that error without contacting the host, so a scan that borrows per file cannot trip a NAS auto-block. "Says the credentials were refused" is recognised from the real protocol errors: `fabric.MarkAuth`, an `AuthFailure() bool` method, a go-smb2 `*ResponseError` with a logon/account NTSTATUS (wrong password, no such user, logon failure, account restriction / disabled / expired / locked out, invalid logon hours / workstation, password expired / must change, logon type not granted), an FTP 530/332/532 reply, a credential-specific text marker, and (WebDAV, which returns no typed error) the text of an HTTP 401 / 407 (and a 403 at login, see `ClassifyLogin`). The memory is **per account** (protocol + settings without the root-selecting keys such as `path`, `share`, `export`), so the three roots of one NAS account make one failed login, not three; a config whose settings identify no account (the factory knows it some other way, as in `pkg/ftp`) is its own account, keyed by its ID; a refusal that is only generic ("access denied" for a share or a file) is remembered for that root alone. A refusal never cuts off the working idle connections of the account's other roots; only NEW logins are refused. The **first login of an account is a pilot**: concurrent borrowers wait for its outcome (one login, not N, when the password is wrong; a transient pilot failure releases the waiters to try concurrently; once one login of the account worked, further logins are not serialised). The memory is cleared by `Evict(id)` (which also lifts the refusal for the other roots of that account), by `CloseAll`, or when the settings change. Transient connect failures are never remembered. Settings that cannot be marshalled have no account identity: no memory, no single-flight (every borrow logs in). `GetClient` may wait for another borrower's pilot login (bounded by `ConnectTimeout`).
- **A skipped probe is not a fault.** `Limited.TestConnection` returns `ErrProbeSkipped` when the host budget is busy; the pool keeps the connection (a dead one fails its first real operation, which `Retrying` handles). Any other probe error still retires the connection.
- **A client the factory hands out twice** (a memoising factory) is refused with `ErrDuplicateClient` before it is connected again or disconnected; the holder's connection is left alone and the pool keeps its capacity.
- **Bounded connect.** A new connection is opened under `ConnectTimeout` (default 30 s) on top of the caller's context, so `GetClient` ("without waiting" means: never waits for a free pool slot; `ErrPoolExhausted`) cannot block without bound.
- **Retirement is lazy.** There is no reaper goroutine; every borrow and return sweeps the expired idle connections of all roots. A connection can outlive `IdleTimeout` until the next pool call.
- A client whose dynamic value is not comparable is refused, never panics, and cannot wedge the pool (the check inspects the dynamic value; the lock is released by `defer`).
- `Pool` keys connections by `StorageConfig.ID`; changed settings under the same ID reset a remembered rejection but need `Evict` to retire idle connections.

## Error classification

`Classify` order: (1) an error marked with `MarkAuth`, one that reports `AuthFailure() == true`, or a go-smb2 `*ResponseError` whose NTSTATUS is a logon/account status is auth; (2) a structured FTP reply (`textproto.Error`) is decided by its code: 530, 332 and 532 are auth; every 4yz is transient (RFC 959: "the action may be requested again") **unless the reply text, with no path in front of it, names a refused login** (credential-specific markers only: `"450 /Movies/Access Denied (2019).mkv: ..."` is a file name, not bad credentials), in which case auth wins so that a lockout reply is never retried (the stronger rule, "decide by the command the reply answers", needs the protocol glue, which marks USER/PASS replies with `MarkAuth`); every other 5yz (including 550 and the RFC 2228 policy replies 533 to 536, and 430 which is not an RFC reply) is permanent; (3) otherwise an auth text marker in a **leaf** cause (never in a wrapper that embeds a file name or in a `*fs.PathError`) is auth; (4) `ErrTransient` marks transient; (5) caller cancellation, not-found, permission and `ErrOutsideRoot` are permanent; (6) only positively identified network faults are transient (reset, abort, pipe, timeout, refused, host/net unreachable, EOF, temporary DNS, `net.Error` timeout); everything else is permanent. Limit: a leaf error whose own message embeds a file name and was built without `%w` cannot be told from a server message; protocol glue that knows its login-failure type should call `fabric.MarkAuth`. A wrapper prefix such as `fmt.Errorf("login incorrect: %w", err)` is deliberately not trusted. `MarkTransient` does not override a credential failure (a lockout is never retried) nor the code of a structured FTP reply (a marked 550 stays permanent): the explicit mark wins over everything below those two checks (cancellation, not-found, network-fault classes). `ClassifyLogin` is `Classify` plus the one signal that is only a credential failure at login, an HTTP 403 from the server just connected to; `Pool` uses it for Connect errors. Generic markers ("access denied", "not logged in") are ClassAuth in a leaf error (never retried) but do not prove the account bad: `Pool` remembers them per root.

## Composition

`fabric.Chain(c, Metered, Retrying, Limited, Confined, ReadOnly)` applies the FIRST decorator outermost. Recommended order: Metered outermost (one sample per final outcome), Retrying around Limited
(each attempt takes a fresh budget slot), Confined and ReadOnly next to the protocol client.

## Streams and the budget

A `Limited` stream holds its slot until `Close`; `Close` is idempotent. `Stats().Held` and `OldestHeld` show unclosed streams. With `WithStreamLease(d)` the lease is **idle-based**: every byte read (`Read`, `ReadAt`, and `WriteTo` while it copies) restarts the clock, and the slot is released once the stream has been idle for `d`. A stream that is actively read, such as a two-hour movie, keeps its slot for its whole life and the cap holds (the round-2 absolute lease let the host see `MaxConcurrent`+1 operations for as long as such a stream was read: measured 34, 35 and 35 other operations in 400 ms by the WF24 review). An expired stream stays readable but its slot is gone for good, so the host can see `MaxConcurrent`+1 operations from the moment such a stream is read again after being idle past `d`. Without a lease a leaked stream starves every protocol sharing the host, which is the documented contract. The lease timer runs on the real clock, not on the budget's injected `Clock`.

- Names are matched by words, not substrings, in `RedactConfig` (`Pass`, `PW`, `PrivKey` are secrets; `Bypass`, `Passive`, `HostKey` are not); a secret stored under a name that denotes none is not recognised, and the allow-list approach (a protocol client returning its own `PublicConfig`, as `pkg/ftp` and `pkg/sftp` do) is stronger.
- Windows-style trailing dot/space and Unicode normalisation tricks in `Confined` are not modelled; the comparison is exact and therefore stricter than a case-insensitive server, but a server that maps a differing name onto the same file is UNCONFIRMED.
- `Confined` is lexical: a server-side symlink or junction inside the root that points outside it is followed by the server. This follows from the code and was not probed (no server). Use a server-side jail (a read-only account, an export root) as well.
- Nested retries: `pkg/sftp` `Connect` already retries internally; `Retrying` treats `Connect` as retryable, so the attempts multiply. Wrap such a client with a policy that accounts for it.
- An instance of `Limited` around a pooled client shares the budget with the pool's login (`Connect`): a host whose budget is held by long streams delays new logins up to `ConnectTimeout`.
- Stream read errors are not part of the `Metered` sample (only bytes and the open outcome).
