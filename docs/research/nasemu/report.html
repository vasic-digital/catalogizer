3. Conclusions

  1. Lite tier: reuse the proven Catalogizer approach (rclone serve ftp/sftp/webdav/http/nfs + real smbd) and generalise it into Containers; add Garage (or SeaweedFS, Apache-2.0) for S3; add a "real server" fidelity option (ProFTPD/vsftpd) later. Kernel NFS and NFS-Ganesha are not rootless-feasible; rclone serve nfs is the evidenced path.
  2. VM tier: vdsm (MIT, very active, v7.67 yesterday) is the only sensible DSM route; its EULA problem (Synology hardware only) is explicit in the project's own FAQ and cannot be mitigated technically — operator attestation is the only gate. XPEnology loaders add circumvention connotation: exclude. macOS: project itself restricts to Apple hardware: opt-in only. Windows: operator-supplied licence.
  3. Host: KVM works for this user via ACL, but RAM headroom (~16 GiB), 57 GiB free disk, and load ~20 make the VM tier admit-or-refuse material; hostbudget lacks a disk axis.
  4. No open-source Synology API mock exists; a lightweight shim would be new code.
  5. Remaining UNCONFIRMED: rootless viability of vdsm/dockur (tun, NET_ADMIN, vhost-net), Synology API PDF parameter details, vsftpd/unfs3/Apache/nginx licences from primary pages, Unraid, whether /dev/sda1 (7.3T) is mounted and free.
