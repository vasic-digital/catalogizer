3. Catalogizer device legs: what emulation can and cannot prove

Sources: docs/CONTINUATION.md Rev 20 (lines 16, 26-27, 37, 67, 87-91, 98-100) and docs/FOLLOW_UPS_NEXT_PHASE.md (lines 1503-1520 Android/Tauri, 1425/1578/1614 second LAN host, 605/1245/1384 Synology, 1617-1699 Tauri wizard).

Rule applied. Under §11.4.289 an emulator running the REAL artifact (the real APK, the real Tauri binary) against the REAL API is LIVE-class evidence for claims scoped to the emulated target; it is not a test double. Two limits bind every row below:

  • The record must carry the §11.4.289(D) fields: artifact sha256, AVD/system-image identity (ro.build.fingerprint, system-image source.properties), emulator version, container image digest, endpoint actually reached.
  • §11.4.298(B), verbatim: "An emulator, a simulator, a host-only run, a replayed or copied record, or a run on hardware of another product is never this run." So no emulated run makes a product RELEASABLE under the release gate; Android, Android TV and any hardware-bound product stays BLOCKED-NO-HARDWARE for deploy/tag purposes until real hardware is connected. Emulation raises PROVISIONAL items to VERIFIED only for the emulated-target claim, and the item text must say which target.

4. Gap list for the Containers submodule

Each gap: proposed API, tests written first (RED captured on the current code, §11.4.224 / §11.4.292), paired mutants, size (non-test LOC + test LOC, estimate), host-safety notes. All new code is project-agnostic (§11.4.28): Catalogizer names, ports and IPs are consumer DATA.

G1. Typed resource and device options in the run primitive (pkg/runtime)

  • API: WithRunMemory(bytes), WithRunMemorySwap(bytes) (default = memory, i.e. no swap), WithRunCPUs(float), WithRunPidsLimit(n), WithRunDevice(path) (validated: must exist, must be in an allowlist the caller passes; /dev/kvm opened O_RDWR first), WithRunUserns("keep-id") (podman only; docker returns a typed error), WithRunPublish(hostIP, hostPort, ctrPort, proto) (hostIP REQUIRED, 0.0.0.0 refused unless WithRunPublishAllInterfaces() is explicit), WithRunLabel(k,v), WithRunImageDigest(ref) (refuses a mutable tag when digest pinning is requested). Never --privileged, never --network host: both refused at the builder with a typed error.
  • Tests first: arg-builder table tests (each option present/absent), refusal tests (privileged, network host, 0.0.0.0 publish, docker + userns), a podman-real test gated on podman presence that runs alpine:3.20 (already on host) with --memory and reads /sys/fs/cgroup/memory.max inside to prove the limit is real.
  • Mutants (>=4): drop the memory flag; drop the -- before image; allow --privileged; treat a tag as digest.
  • Size: ~250 + ~400 LOC. Unblocks Catalogizer deviation (b) (scripts/containers/run_pinned.sh:44).

G2. Host-safety admission + emulator envelope (pkg/emulator, shared helper in pkg/policy or new pkg/hostbudget)

  • API: hostbudget.Admit(req Need) (Verdict, Evidence) with Need{MemBytes, CPUs, Pids, NeedsKVM}; verdict closed set fits | does_not_fit | undetermined (mirrors §11.4.291 vocabulary); inputs /proc/meminfo MemAvailable/MemTotal, /proc/pressure/memory and /proc/pressure/cpu, loadavg vs nproc, ulimit -u, /dev/kvm O_RDWR probe (read-only intent: open+close, no ioctl). Reserve and thresholds are consumer DATA; defaults = §12.6 60% ceiling, MemAvailable - need >= max(4 GiB, 15% MemTotal). ContainerizedConfig gains Memory, CPUs, PidsLimit (host-adaptive defaults; emulator default memory = AVD RAM + 1.5 GiB overhead, CPUs = min(3, 0.25*nproc)); Boot refuses on does_not_fit or undetermined with a typed error and writes the evidence JSON. Replace kvmAvailable stat (pkg/emulator/containerized.go:37) with the O_RDWR probe from pkg/vm/qemu.go:163.
  • Tests first: fake /proc fixtures (golden-good fits, golden-bad does_not_fit, unreadable PSI -> undetermined, carrier: high load but low memory need is still judged by both axes); KVM probe with a temp char-device stand-in is not possible, so test the error-mapping seam plus one real probe on hosts with /dev/kvm.
  • Mutants: stat instead of open; ignore PSI; treat undetermined as fits; drop --memory from run args.
  • Size: ~300 + ~500 LOC.

G3. Host-SDK-mount containerized emulator (no multi-GB image pull)

  • Problem: the gate-eligible Linux runner needs an emulator image; the base android-emulator-base:latest is absent and disk is at 97%. The host already has the SDK, emulator 37.1.11 and both API 34 system images.
  • API: ContainerizedConfig.SDKMount{HostPath, ReadOnly: true} and AVDHome (scratch dir, rw): run a slim image (Debian bookworm-slim, already on host, plus the emulator's runtime libs: libpulse0, libnss3, libxcomposite1, libxcursor1, libxi6, libxtst6, libasound2, socat) with the host SDK bind-mounted read-only at /opt/android-sdk, AVDs created by avdmanager inside the container into the scratch AVD home. New images/android-emulator-slim/Containerfile; image built locally (one ~150 MB layer, no SDK inside). Record the system-image source.properties and ro.build.fingerprint in BootResult.
  • Tests first: arg-builder tests (mount ro, AVD home rw, no write mount on the SDK), avdmanager command builder for -d pixel_6 -k "system-images;android-34;default;x86_64" and -d tv_1080p -k "system-images;android-34;android-tv;x86"; live boot test gated on KVM + host SDK + admission fits.
  • Mutants: rw SDK mount; wrong -k tag for TV; skip fingerprint capture; omit --userns=keep-id.
  • Size: ~350 + ~450 LOC + Containerfile ~40 lines.

G6. Secret-safe text input (pkg/emulator)

  • Problem: AND-FU-3, adb shell input text <password> exposes the secret in the HOST process table.
  • API: TypeSecret(ctx, serial, secretFile string): pushes the 0600 file to /data/local/tmp/<random> via adb push (path in argv, value not), runs adb shell 'input text "$(cat F)"; rm -f F' with the command string free of the value, then verifies with uiautomator dump that the field is non-empty and masked. Secret never logged; evidence redacts.
  • Tests first: argv never contains the secret (property test over random secrets), file removed on success and on failure path, refusal when the file is not 0600.
  • Honest limit: the value is briefly in the device's own shell process; acceptable for an emulator (UNCONFIRMED whether the operator accepts it).
  • Mutants: secret in argv; no rm; mode check skipped; no post-type verification.
  • Size: ~150 + ~250 LOC.

G8. Virtual LAN peer + protocol-server fixtures (extend pkg/network, new pkg/fixtures)

  • API: network.CreateBridge(name, subnet) (rootless netavark, internal by default), fixtures.Peer{Network, IP, Services []Service} with typed services SMB{Share, Path, Users from 0600 file}, NFSUser{Export, RO} (userspace), FTP{Explicit/Implicit TLS}, SFTP, WebDAV, S3Garage; each with a protocol-level health check (SMB: smbclient -L or a Go SMB negotiate; NFS: MOUNT/NULL RPC; FTP: banner + login; WebDAV: PROPFIND 207; S3: signed ListBuckets) and a fault API Cut() / Restore() (disconnect the peer from the bridge) for cut-recovery tests. Corpus mounted read-only except a declared rw/ subdir. Ports: inside the bridge the real ports (445, 2049, 21) are used; no host publish unless asked.
  • Tests first: arg builders, health checks against fixtures that answer wrongly (golden-bad: FTP banner but login refused must not be "healthy"), cut/restore state machine, real-podman test on alpine.
  • Mutants: health = TCP connect only; publish on 0.0.0.0; corpus rw; Cut() that does not detach.
  • Size: ~800 + ~1000 LOC + 4 small Containerfiles (Samba, vsftpd, WebDAV, NFS-userspace; reuse atmoz/sftp and dxflrs/garage:v1.0.1 already on host).
  • Honest limit: proves "different IP over a virtual L2 link", never a physical second machine.

G9. Containerized QEMU runner (pkg/vm)

  • Problem: pkg/vm/qemu.go:173 launches qemu-system-* on the host; the host has none.
  • API: vm.NewContainerizedQEMU(cfg{Image, Memory, CPUs, KVM}) implementing the existing VM interface (pkg/vm/types.go:179); --device /dev/kvm, --userns=keep-id, qcow2 base read-only + -snapshot, networking either user-net with SSH hostfwd (existing) or -netdev tap inside the container attached to a G8 bridge (container has /dev/net/tun via --device, no privilege). -m/-smp from config instead of the hardcoded 2048/2 (pkg/vm/qemu.go:196-197).
  • Tests first: arg builder parity with host runner, refusal without admission, live boot of alpine-3.20-x86_64 gated on KVM (image fetched only through pkg/cache with sha256; not now: disk).
  • Mutants: hardcoded memory; missing -snapshot; rw base image; tap without tun device.
  • Size: ~400 + ~500 LOC + Containerfile.

G10. Windows guest target (pkg/vm, later)

  • API: VMTarget{Distro: "windows", ...} + OVMF + swtpm (TPM 2.0) inside the G9 container; image ONLY from an operator-supplied path with licence DATA (licence: evaluation|retail, expiry); never auto-download; boot readiness via WinRM or OpenSSH-for-Windows.
  • Blocked now: disk (Windows image 20-30 GiB vs 58 GiB free), licence decision (operator), host load.
  • Size: ~600 + ~600 LOC. Record SKIP reason topology_unsupported until the operator supplies an image.

G11. Reachable-endpoint resolver (pkg/emulator, pkg/desktopgui)

  • Problem: inside a rootless pasta container the host LAN IP resolves to the container (scripts/tauri/run-qa.sh:10-12); inside the Android emulator the host is 10.0.2.2. Every run must record which URL it actually used.
  • API: ReachableAPI(target, hostPort) (url, evidence) returning http://10.0.2.2:<p> (emulator), http://host.containers.internal:<p> (container), or a G8 bridge IP, with a probe from inside the target (curl/adb shell toybox nc) recorded as §11.4.289(D) endpoint identity.
  • Size: ~150 + ~250 LOC.

G12. Device leases for emulated devices (reuse §11.4.119 / §11.4.176 pattern)

  • API: lease keyed by stable AVD name / container name, all-or-nothing, TTL-reaped by kill -0 + cmdline, so parallel agents never drive one emulator. Size ~200 + ~300 LOC. May reuse an existing lease engine in the constitution (UNCONFIRMED whether one is importable by reference; check before writing).
