> `$EV` in this guide means the evidence root `specs/001-full-project-audit-remediation/evidence` (repository-relative).

## Purpose

The one-way sync driver of the findings register (docs/04 section 10.3): it sends the register's items to the external trackers the owner configured, records every attempt in `reg_tracker_sync_log`, and never claims a push that did not happen. With zero configured trackers the correct report is "0 trackers configured; 0 pushes; nothing claimed as synced"; the candidate trackers (GitHub issues, GitFlic, GitLab, GitVerse, Crashlytics, Sonar) are recorded `SKIPPED not_configured` so none is silently absent (T191, FR-004). The register is the single source of truth: remote edits are never read back (a remote status the adapter reports is compared and listed as drift, never applied).

## Usage

```bash
scripts/register/sync_trackers.sh [--config .helix/reporting.yaml] [--db docs/<name>.db] [--dry-run] [--json <file under .audit/ or the evidence_dir>]
                                  [--tracker <name>]... [--limit N] [--max-attempts N] [--backoff-base S] [--adapter-timeout S]
                                  [--batch-size N] [--skip-batch-size N] [--breaker N]
                                  [--approved-by <name> --approve-first-sync <plan hash>] [--retry-indeterminate]
```

* `--dry-run` takes no lock, calls no adapter, writes no database row and no file (except an explicit `--json`); it prints the plan and, for every tracker that would be pushed to for the first time, the `plan_hash` (see "First-sync gate").
* `--max-attempts` (default 3) bounds the attempts per item, `--backoff-base` (default 1 s) doubles per attempt up to 30 s, `--breaker` (default 3) is the number of consecutive persistent failures after which the rest of that tracker's items is not attempted (see "Circuit breaker"), `--adapter-timeout` (default 120 s) bounds one adapter call.
* `--json` is confined to `.audit/` and the configured `evidence_dir` (a path elsewhere is REFUSED `path_invalid`: it used to replace any repository file).
* `--retry-indeterminate` releases items that are held because an earlier push may or may not have landed (see "Selection").

## The consumer config (`.helix/reporting.yaml`, T190)

DATA, variable NAMES only, never values (11.4.10). Keys: `schema_version: 1`, `db: docs/workable_items.db`, `id_prefix: CAT` (must match the prefix the `reg_ids` DDL generates, else REFUSED `config_id_prefix_unsupported`), `default_severity`, `evidence_dir` (now the register-level `$EV/register`, not a work-package folder), `trackers: []` until ODG-10, `candidate_trackers` (names the owner has not decided on), `first_sync_approvers: []` (names allowed to approve a first push; empty = no first push can happen), `first_sync_pilot_max: 5` and `confidential_categories: [danger_zone]` (register categories that are never sent to a public tracker; the register has no `security` category, so which categories hold security findings is an owner decision, UNCONFIRMED). The file is shared with the constitution engine `report_item.sh` (its keys `default_reported_by`, `sync_command`, `workable_items_bin` are accepted and ignored here). Unknown keys and DUPLICATE keys are REFUSED (`config_malformed`): the last duplicate key used to win silently, so a second `required_env: []` could disable the credentials check, and a second `trackers: []` removed every tracker.

A tracker entry: `name` (lowercase word), `command` (adapter command; `{db}` and `{id}` are the only placeholders; absent = not configured, empty or missing executable = client absent), `required_env` (names, upper or lower case; a name that is unset, EMPTY or blank gives `credentials_absent`), `env_passthrough` (a MAPPING NAME to template, the shared contract with `report_item.sh`, which calls `.items()` on it; the list form is REFUSED, and every template MUST contain `{db}` or `{id}`, because a literal value could be a credential: REFUSED `config_secret_in_env`), `enabled: false` (recorded `disabled_by_operator`, `reg_trackers.enabled = 0`), `public` (default `true`: fail closed), `kind`.

**Credential guard (`config_secret_in_command`).** The command line is checked against a positive grammar, not a deny-list. REFUSED: a user:password@ URL; any Authorization/Bearer/`PRIVATE-TOKEN`/`X-API-Key`/header text or the flag `-H`/`--header`; any credential-shaped token (`ghp_`, `glpat-`, `xox?-`, `AKIA`, `AIza`, `sk-`, `eyJ...`); a key or flag whose NAME marks a credential (token, secret, password, api-key, auth, credential, bearer, private-key, access-key, cookie, jwt, signature, pat) carrying a value, either as `--flag=value` or as `--flag value`, unless the value is a `$NAME` reference or a placeholder (a `--token-file=path` is allowed); a single-letter flag followed by a bare word (`-t value`; value-bearing short flags are ambiguous, use a long flag). A `$NAME` reference reaches the adapter argv as that literal text; the driver never expands it. The command text is NEVER written to the register: `reg_trackers.command_ref` holds `<executable>#sha256:<16 hex>` (changing the command changes the digest). The guard cannot prove a command is free of secrets (a secret in a bare word that looks like a path is not detectable); it closes the classes in the review's 18-form probe and the forms listed above.

## Behaviour

1. **State of a tracker**, in this order: `disabled_by_operator`; no `command` key: `not_configured`; empty command or an executable (or interpreter script, also behind `env [NAME=v]`/`/usr/bin/env`) that does not exist: `tracker_client_absent`; a `required_env` name unset, empty or whitespace: `credentials_absent` with exactly those NAMES in `missing_env_names`; else the adapter runs. The values of the environment are never read into any output, row, journal, batch file or log; a value written in the CONFIG is refused by the guard above (it used to be accepted for 10 of 14 forms and persisted).
2. **First-sync gate** (docs/04 10.3, 11.4.252): a tracker in the adapter state with no `SYNCED` row yet is pushed to only when the run carries `--approved-by <name>` (a name in `first_sync_approvers`), `--approve-first-sync <plan hash>` (the hash a `--dry-run` printed for exactly this item set and config) and `--limit N` with `N <= first_sync_pilot_max`. Anything else is REFUSED `first_sync_gate` (20) before any write; an item added after the dry run changes the hash. After the pilot has `SYNCED` rows the gate no longer applies. Honest limit: on a single-uid host nothing stops the same actor from running the dry run and passing the approval; the gate prevents an accidental mass push and records the approver, it does not separate duties (11.4.240 needs a host boundary that agents cannot create).
3. **Selection**: per tracker, the items whose latest `reg_tracker_sync_log` row is absent, `SKIPPED`, `FAILED` or of a different `item_revision` (sha256 of id, title, body, status, type, severity). A `SYNCED` row of the same revision is left alone. A tracker-level `SKIPPED` that repeats the latest `SKIPPED` row writes no new row (`unchanged_skipped`). **Held:** an item whose latest row is an indeterminate `FAILED` (124 timeout, 75 crash: the push may have landed) and whose remote reference is unknown is not pushed again (`held_indeterminate`, exit 7) until `--retry-indeterminate`. **Withheld:** an item of a `confidential_categories` category on a public tracker, or whose title or body matches a credential pattern, is recorded `FAILED` 78 / 77 WITHOUT an adapter call and is not re-recorded while unchanged; the matched text is never printed. These patterns are heuristics (false positives are possible and visible, false negatives are possible and not).
4. **Adapter contract** (consumer-owned script): stdin (a file) = one JSON object `{db, tracker, atm_id, title, body, status, type, severity, evidence_dir, idempotency_key, remote_ref?}` (no secret in argv or stdin; `remote_ref` present means UPDATE that remote issue; `idempotency_key` = `tracker:id:revision` for the adapter to deduplicate); environment = `PATH`, `HOME`, `LANG`, `TMPDIR` plus the declared `required_env` and `env_passthrough` names only; stdout's last line = `{status: SYNCED|SKIPPED|FAILED, skip_reason?, missing_env?, remote_ref? (string or integer), remote_state?, evidence_path?}`. The adapter runs in its OWN process group with stdout and stderr redirected to files (a stray child can neither hold the result hostage nor outlive the call: the group is killed after the call and on timeout, with the 11.4.263 guard `pgid > 1 and pgid != own group`). Undecodable output bytes are replaced, not fatal. A `SYNCED` claim needs process exit 0, a printable-ASCII `remote_ref` and a receipt file that (a) lies under THIS run's evidence directory, (b) was written during the call, (c) is non-empty and (d) names the item id and the returned reference; anything else is recorded `FAILED` (65 for reference or receipt, 70 for unusable output, 124 for a timeout, the process exit code otherwise). A non-conforming reference is kept sanitized on the `FAILED` row (so the next push updates instead of creating). The process exit code beats the adapter's own claim. An adapter `SKIPPED` may only use `credentials_absent`, `tracker_client_absent` or `unreachable`; `unreachable` is retried within the bounded attempts. A timeout of a create is not retried (it may have landed). `remote_state`, when the adapter reports it, is compared with the register status and listed as drift (`drift N item(s)` and the JSON `drift` array); the register has no column for it, so it is not stored.
5. **Write-ahead journal** (`.audit/sync/wal/<run>.jsonl`, fsync): an `intent` record before every adapter call and its `result` right after it; a batch write adds `flushed`; a clean end adds `closed`. If the journal cannot be written, nothing is pushed (the exception exits 5 before the call). The NEXT run reconciles every unclosed journal first: results never written are written (rows already in the register are skipped), an intent without a result becomes `FAILED` 75 (held, see 3), and the recovered reference is what the adapter is handed on the next change. SIGTERM, SIGINT and SIGHUP flush what is pending (exit 6); an unexpected exception exits 5.
6. **Single writer** (round-23 review I6): the driver opens the database read-only (python `sqlite3`, `mode=ro`, closed right after each read) and writes only through `scripts/register/locked.sh`: one call per batch, `sqlite3 -bail /src/<db> ".read /src/.audit/sync/<run>/batch-NNN-<label>.sql"`, `PRAGMA foreign_keys=ON` first, one transaction. Each call is a row of `.audit/register/journal.jsonl` with the batch file captured as an input. A `SYNCED` row is written with its `reg_evidence` row (`tracker_receipt`, class `artifact`, path, sha256, size) in the same transaction. **Exit 21/22 of the wrapper** (the write ran but its journal row did not / the container's exit status is unknown) are checked by READING THE ROWS BACK: rows found are reported as verified, rows not found as unrecorded. A refusal of the wrapper for host memory, CPU or disk (`run_pinned REFUSED reason=memory_budget_unavailable` and its siblings: nothing ran) is retried 6 times 15 s apart; the budget is never overridden. Read-only access to a WAL database can leave `-wal` and `-shm` files next to it; this guide does NOT claim the readers are invisible to the file system.
7. **Failure of a register write**: exit 4, the rows that were not recorded (with their `remote_ref`) stay in `.audit/sync/<run>/unwritten.jsonl` and in the write-ahead journal, and the next run writes them before anything is pushed. A failed mint of one tracker's item no longer stops the other trackers; its reason (the wrapper's last lines) is printed.
8. **Skipped trackers are tracked items** (T191, analyze-remediation A18, 11.4.214): for each tracker and reason in `not_configured`, `tracker_client_absent`, `credentials_absent`, `unreachable`, `failed` one register item is minted through the `reg_ids` path under `locked.sh` (type Task, `mint_basis = reporting_directive`, `reg_item_ext` category `gap`, `minted_by = sync_trackers:<tracker>:<reason>`). The key is looked up first, so one tracker and reason is never minted twice. **Owed reopen:** when the item is already terminal (`(→ Fixed.md)`) and the tracker is skipped again, the driver prints `OWED reopen of <id>` and exits 7 on every run until the register custody path reopens it. The driver cannot perform that reopen itself: `reg_recurrence_links` requires a reported source entry or finding, and a driver observation has neither (inventing one would be a fabricated record). `disabled_by_operator` is an operator decision and mints nothing (UNCONFIRMED reading of "SKIPPED tracker" in tasks.md T191). Items minted in a run are synced in the same run.
9. **Circuit breaker**: `--breaker` consecutive failures of one tracker. If every failure of the streak was `unreachable`, the rest of the tracker's items is recorded `SKIPPED unreachable` without a call (`breaker_skipped`). If the tracker ANSWERED (a `FAILED`, a rejection), it is not unreachable: the rest is NOT attempted and NOT recorded (`breaker_open`), and the minted item is the `failed` one. A `SYNCED` call resets the streak.
10. **Trackers and the stale view**: `reg_trackers.enabled` follows the config (0 for `enabled: false`); on a FULL run (no `--tracker`) a tracker the config no longer names is retired (`enabled = 0`) and `v_stale_tracker_sync` stops listing it; a subset run never retires. A disabled or retired tracker therefore has no rows in `v_stale_tracker_sync`: the T575 reading "empty or every row SKIPPED with its reason" applies to the enabled trackers.
11. **Concurrency**: one driver at a time (exclusive `flock` on `.audit/sync/driver.lock`, else REFUSED `sync_already_running`); one in-flight adapter call per tracker; trackers run one after the other and each tracker's rows are flushed at its boundary.
12. **Report**: one line per tracker (`state`, `selected`, `synced`, `skipped` by reason, `failed`, `unchanged`, `unchanged_skipped`, `breaker_skipped`, `breaker_open`, `held_indeterminate`, `withheld`, `missing_env_names`), the first-sync plan hash, the minted items, drift, retired trackers, and the `v_stale_tracker_sync` summary (T220 criterion 3, T575 and T574a read it). `--json` writes the same with an identity block (git head, sha256 of the driver, the wrapper and the config, run id), the first-sync plan and the list of wrapper calls.

## Exit codes

0 ok (SKIPPED rows are honest results, not errors); 1 at least one item ended `FAILED` (withheld items do not count); 2 usage; 3 database missing, not SQLite or not a register; 4 a register write failed; 5 internal error; 6 interrupted by a signal; 7 attention needed: an owed reopen or held indeterminate items; 20 `REFUSED reason=<code>` (`config_missing`, `config_malformed`, `config_secret_in_command`, `config_secret_in_env`, `config_id_prefix_unsupported`, `first_sync_gate`, `path_invalid`, `sync_already_running`, `locked_missing`).

`LOCKED` and `LOCKED_ROOT` are test hooks, honoured only with `LOCKED_TEST_MODE=1`.
