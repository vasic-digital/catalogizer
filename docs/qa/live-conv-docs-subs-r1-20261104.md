## Defects (all reproduced 3/3; product defects unless marked)
D1 (HIGH, product) Document conversion is unreachable/broken for every advertised document format. Evidence: jobs 80-83, 86 (+r2/r3) `ebook-convert ... not installed`. Root cause 1: `services/conversion_service.go` `convertDocument` tests `isEbookConversion` first; its list includes txt and html, so pdf->txt / pdf->html (and txt->pdf) are routed to calibre `ebook-convert`, never to `convertPDF`/`convertPDFToText` (the CAT-002 isolated poppler/pure-Go extractor). Root cause 2: runtime image (Dockerfile/Dockerfile.runtime) has no calibre and no libreoffice (`which` empty), while GetSupportedFormats advertises epub/mobi/pdf/docx/odt. Result: the CAT-002 isolated PDF text path and convertPDFToImage/HTML are dead via the API; the advertised pdf->png is also rejected by validation (document outputs: epub, mobi, pdf, txt, html only). Fix: check `isPDFConversion` before `isEbookConversion` for source pdf, add pdf->image outputs or remove convertPDFToImage, and either install calibre/libreoffice in the image or drop epub/mobi/azw/docx/odt/txt->pdf from the advertised formats and fail validation (400) instead of accepting a job that can never run. Spec defect as well: formats endpoint advertises what the runtime cannot do.
D2 (MEDIUM, product) `DELETE /conversion/jobs/:id` is a cancel alias: `DeleteJob` calls `CancelJob` and returns "Job deleted successfully". On a running job it cancels (row remains, status cancelled); on a terminal job it returns 409 "cannot cancel job in status: completed". No job can ever be deleted; job rows and output files accumulate (my jobs 75-134 and outputs /app/data/qaconv_*, qalife_*, qax_* remain on stack 3; not removable via the API). Fix: implement real delete (+ output file removal confined to the conversion roots).
D3 (MEDIUM, product) `GET /entities/:id/pdf-pages[/:n]` on a malformed PDF (entity 7 `not-a-pdf.pdf`) returns 500 with internal detail `open pdf document: fitz: cannot open document`. Malformed user content should map to a 4xx (415/422) with a generic message; the handler also parses untrusted PDFs in-process with go-fitz (MuPDF cgo), outside the CAT-002 process isolation (which only covers text extraction). Fix: map the open error to 422; render via the isolated child/poppler (pdftoppm) path.
D4 (MEDIUM, spec/product) No full-text search over extracted document text: `/search/files?q=ZEBRA-4242` and `q=OKAPI-1357` return 0 although the fixtures contain them (filename search works: q="Known Text Document" finds 1). No text-extraction-to-index step exists. If advertised, it is missing; if not, document it. (`query=` is not a parameter; `q=` is.)
D5 (HIGH, product, bluff-class) `GET /subtitles/:id/verify-sync/:media_id` is tautological: `extractSamplePoints` sets `VideoTime = SubtitleTime`, so offset is always 0 and confidence a constant 0.8. The out-of-sync SRT (all cues +7s on a 5s video) is reported `is_valid:true, confidence 0.8, offset 0`, identical to the in-sync SRT (ids 1/4, 5/8, 9/12 x3). Also `parseSubtitleLines` is SRT-only, so valid VTT and ASS uploads yield 0 frames, `is_valid:false`, "poor" without an error. `getVideoInfo` duration is read but never compared. Unknown media id (99999999) also returns 200. Fix: compare cue range with media duration (ffprobe/metadata) and implement VTT/ASS parsing, or return 501 until real.
D6 (MEDIUM, product) `POST /subtitles/upload` with a non-existent `media_item_id` -> 500 SAVE_ERROR (should be 404), and with binary garbage content -> 500 (should be 400/422: invalid UTF-8/format validation). Format is derived from the file extension only; content is never validated.
