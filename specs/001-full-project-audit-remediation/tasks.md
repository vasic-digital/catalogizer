**Organization (deviation from the template, stated)**: the template groups phases by user story. ## Format: `- [ ] Tnnn [P] [USn] [markers] Description with exact path`

- **[P]**: parallel-safe (different files, no unfinished dependency)
- **[USn]**: user story from spec.md (US1..US7)
- **[TDD]**: RED-GREEN-REFACTOR, RED observed on the broken artifact before implementation
- **[REVIEW]**: independent Opus-xhigh review gate (11.4.142/11.4.209), reviewer stream separate from producer (11.4.240)
- **[SUBAGENT]**: can be delegated to a subagent
- **BLOCKED-ON ODG-nn**: waits for the owner decision (doc21 section 8, research.md OD ids); the safe default is stated where research.md defines one
- Paths marked `(new)` do not exist yet and were chosen by the plan; the reviewer confirms them

## Constraints that bind every task

Rootless Podman containers only, builds distributed via the containers submodule (11.4.173); no CI/CD (11.4.156); no force-push, ff-only to all upstreams (11.4.113); all work on main branches (FR-024); no credential value in any file (11.4.10); a real service or device is required for every non-unit check, and when it is absent the result is `blocked-unavailable`, never a pass (spec clarification A2); every fix leaves a RED, three GREEN, a caught mutation and an independent GO review (docs/04, docs/06).

**Source**: docs/21 §3.3 (P0, P1), §4, §5.1, §5.2, §8, §10; detailed steps in docs/02, 04, 06, 11, 12, 15, 16, 19, 20.

**Phase-group conventions (P0-P1)**

- `$FEAT` = `specs/001-full-project-audit-remediation`; `$EV` = `$FEAT/evidence` (ledger, anchors, blobs, verdicts, docs/06 §11); `$AUD` = `$FEAT/audit`.
- `RUNP <IMG-ID> -- <cmd>` = `scripts/containers/run_pinned.sh <IMG-ID> -- <cmd>` (delivered by T006): resolves `<IMG-ID>` to `reference@sha256:<digest>` from `build/containers/images.lock.yaml`, runs rootless podman with `--userns=keep-id --cap-drop=ALL --memory --memory-swap --cpus --pids-limit --label project=catalogizer --label op_id=<id>`, `-v "$PWD":/src:ro -v <out>:/out:rw`; refuses a tag-only or unresolved image.
- Every executable artifact is test-first (§11.4.224): the test task precedes the implementation task and the RED run is captured before code exists; every gate ships a paired §1.1 mutation that is observed failing before the gate is trusted (G-GATE).
- Until `tools/evidence/evrec` exists (WP-05), evidence is a transcript under `$EV/<wp>/` plus `$EV/<wp>/SHA256SUMS`; T002 re-records every P0 transcript as an `ev/1` ledger entry (`contracts/evidence-record.schema.json`).
- Before WP-04 lands, commits are plain fast-forward commits on `main` (never `--force`, never a rewrite); after WP-04 every commit goes through `scripts/commit-push-all.sh` (docs/21 IC-16).
- Read-only `git`, CodeGraph CLI reads, Lumen read-only calls, the read-only verifier and the control-plane `podman run` launcher run on the host (docs/16 §5, §18); everything that compiles, tests, lints, scans or renders runs in a pinned rootless container.
- `[REVIEW]` tasks are owned by stream ST-REV (Opus, xhigh, §11.4.209), never by the producing stream, iterated to zero blocking findings (§11.4.134), verdict files under `$EV/reviews/`.
- `BLOCKED-ON ODG-nn` means the step waits for the owner (docs/21 §8); a documented research.md default is named where one exists; a missing device, host, credential or service is recorded `blocked-unavailable` with its reason, never a pass (FR-025).

## Dependencies and execution order

- Phase order is strict at the exit gates: **P0 -> P1 -> P2 -> P3 -> P4 -> P5 -> P6 -> P7**. The gate evidence for each phase is the `Checkpoint` line of its last work package plus the human checkpoints HC-1..HC-n in docs/21 section 3.3.
- Inside a phase, work packages follow the Inputs column of docs/21 section 5 (diagram in docs/21 section 5.9, acyclic, checked by script). Tasks marked `[P]` inside one work package, and work packages with disjoint Inputs, may run concurrently, bounded by the host limits in docs/21 section 4.2 (60 percent memory ceiling, process-limit headroom, at most 6 concurrent agents).
- Producer and reviewer streams are separate: `[REVIEW]` tasks belong to ST-REV and never to the stream that produced the work (WP-39R, WP-74R).
- Owner-blocked tasks (`BLOCKED-ON ODG-nn`) are skipped, not guessed; the autonomous loop continues with every unblocked task and records the block (docs/21 section 8).

- **Forward references**: 16 tasks name a later task as an explicit dependency (T007 after T018, T007 after T062, T007 after T065, T010 after T070, T010 after T074, T017 after T069, T030 after T078, T031 after T063, T054 after T069, T056 after T069, T168 after T201, T236 after T237, T253 after T257, T292 after T297, T347 after T352, T439 after T463). Such a task is scheduled after its dependency regardless of its position in this document; the explicit-dependency graph over all tasks was checked and is acyclic.

## Implementation strategy

1. **MVP / first deliverable**: P0 and P1 (verifier, evidence recorder, register, pinned containers), then P2 baselines. After P2 exit the register contains every known item and the baselines exist, which already satisfies US1 on its own.
2. **Incremental delivery**: each later phase ends at a checkpoint that is independently demonstrable (audit accepted at G-AUDIT, contract layer, remediation per component, test closure, final verification).
3. **Parallel team strategy**: streams ST-INFRA, ST-QA, ST-GOV, ST-REG, ST-SEC, ST-API, ST-WEB, ST-DESK, ST-AND, ST-SUB, ST-DOC, ST-PERF and ST-REV work in parallel once their phase gate opens.
