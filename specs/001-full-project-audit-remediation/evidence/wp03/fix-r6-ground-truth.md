## Findings that corrected earlier statements (each backed by the row)

1. **P07/P08: a forged commit-graph DOES fool `git merge-base --is-ancestor` when an INTERIOR commit is forged (generation v1 and v2).** Plain rc=0 (wrong), with
   `-c core.commitGraph=false` rc=1. `git log` and `git rev-list` read the forged parents too (P08). Only the TIP variant (P09, what the round-2 reviewer built)
   is not fooled, because git parses the tip from the object named on the command line. Every earlier sentence "git validates the graph", "fools log and rev-list but
   not is-ancestor" and "no false pass was shown" was false or incomplete and is replaced (guide, script header).
2. **P05/P06: `--no-replace-objects` does NOT switch off `info/grafts` in git 2.53**; `GIT_GRAFT_FILE=<absent>` is the only switch, so BOTH are part of the mechanism.
3. **P22-P24: `git config --local --get core.excludesFile` misses include.path / includeIf values (empty), and config.worktree is a different file.**
   `git config --show-scope --get` reports `local` / `worktree` for all three and `global` for a global value, also one reached by an include inside the global file (test P25).
4. **P40/P47/P48: `bash -p` protects only the bash process that carries the flag.** A direct run of the `#!/bin/bash -p` file still EXPORTS BASH_ENV, ENV,
   SHELLOPTS and BASH_FUNC_* to every child: a non -p bash shim sourced the caller's BASH_ENV on every git call (28 times in one run, measured by the r10 test
   before the fix). Only the environment itself can be cleaned: `env -i` with an allow-list (P40 isolated column; P47b: `bash -p` still passes an exported function on to its children).
5. **P30 (core.fileMode=false hides a chmod) is the one surface that fools git and is deliberately NOT switched off**: forcing core.fileMode=true makes a
   checkout on a filesystem without an exec bit read dirty everywhere (a 11.4.201(1) false-positive refusal). Stated boundary; test `P30 BOUNDARY` pins the
   behaviour so a change of it is a visible decision. P31 (core.autocrlf) could not be made to hide dirt on this git: not a finding.
6. **P13-P15: shallow and alternates are not holes**: a shallow file removes ancestry only (a failing class stays failing, never becomes a pass); alternates add
   genuinely held objects (content-addressed), the verdict is true.

## What stays UNCONFIRMED (not claimed)

- Behaviour on other git versions (probe ran on one). The probe is the way to re-measure: `bash fix-r6-probe.sh`.
- `/etc/gitconfig` (system config) and the user's global config are TRUSTED as before (the host owner's own settings); `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL`
  are passed through. Setting `GIT_CONFIG_GLOBAL=/dev/null` was rejected: it would turn the global-only-ignores decision (N1) into false dirt and break
  `safe.directory` in containers.
- A remote helper (`remote.<n>.vcs`), `GIT_SSH` and `GIT_EXEC_PATH` named by the environment stay as stated in the script header.
